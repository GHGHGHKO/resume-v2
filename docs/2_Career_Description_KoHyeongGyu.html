GS25·GSSHOP 통합회원 플랫폼(GRM)

  • 인증·인가: 비밀번호 찾기 OTP 우회와 타 계정 정보 접근 취약점을 수정하고 가입·재가입 정책을 개선했습니다.
  • 개인정보: 통합회원 동기화·분리보관·복제 DB 경로의 CI 암호화와 배포 전환을 수행했습니다.
  • 로그 최적화: 중복 요청 파라미터 로그 155건과 불필요한 UI 로그를 정리했습니다. 트래픽 보정 전후 비교에서 본인 담당 변경분은 약 43.5GB/일, 팀 1차 배포 기준 GRM 전체는 약 87GB/일(40.7%) 감소했습니다.
  • 운영 도구: production 대상 PR과 운영 관측 데이터를 함께 검토하도록 AWS Lambda 기반 AI 코드리뷰 봇을 설계·구축했습니다.

GS네트웍스 → GS리테일 GS25 라이프스타일플랫폼팀 | 2021.08–2025.10

2022.10 사내 인사이동으로 소속 회사가 변경됐습니다. 택배 서비스 인증·제휴 연동·AWS 이관을 담당했습니다.

우리동네GS 택배 인증·인가 서버 (blackpink)

  • Java 21, AWS KMS, Spring Security 기반 stateless 토큰 발급·검증·갱신과 연동 시스템별 인가 규칙을 설계·구현했습니다.
  • GRM 발급 토큰 검증과 회원 식별을 담당했습니다. 실제 회원 계정 연결 API는 다른 담당자의 작업입니다.
  • 예약·주소 등 고객 데이터의 소유자 접근을 제어하고 현장 장비 약 18,000대 및 키오스크 게스트 인증을 구현했습니다.

편의점택배·방문택배 백엔드

  • 주요 업무 서비스는 Java 11을 사용했습니다. 토스·네이버·번개장터·쇼피 등 10여 개 제휴사의 접수·배송 상태 연동을 개발·운영했습니다.
  • 점포 POS 취소 신호를 연동해 환불 뒤 동일 운송장을 재접수하는 어뷰징을 차단하고, CJ대한통운 미접수 연동을 FTP에서 OpenAPI로 전환했습니다.
  • 우리동네GS 택배 예약·주소록 API와 방문택배 접수·취소·상태 처리 백엔드를 개발했습니다. 취소 코드 누락으로 미처리된 86건의 작업을 수정 배포 후 1시간 26분 만에 복구했습니다.

IDC → AWS 이관 (팀 공동 작업, 2023.01–2024.04)

  • 내부 3명과 필요한 기간 참여한 외주 3명이 협력했습니다. 13개 서비스와 서로 다른 테이블 구조의 PPAS DB 2종에 대한 이관이 팀 공동 범위입니다.
  • 본인은 Airflow 설계·이관, DAG 정비·배포 자동화, Core API·배치 SQL 전환, 순차 운영 배포와 외주 인력 온보딩을 담당했습니다.
  • 동일 Spring Batch 이미지를 IDC·AWS 양쪽에 배포하고 실행 상태를 확인한 뒤 DAG를 순차 전환했습니다. 문제 발생 시 IDC로 복귀 가능한 절차를 마련했습니다.
  • 미사용 DAG 정리와 저처리량 제휴사 20곳의 Flow 통합으로 DAG를 250개에서 170개로 줄였습니다.
  • Fargate 약 200초와 EC2 약 80초의 배치 준비 시간을 비교해 EC2 실행 환경을 선택했습니다. 전체 처리 시간 감소율이나 운영 비용 절감률은 측정하지 않았습니다.
  • 기존 실패 지점 재개 구조를 활용해 Job 재시도·SNS 알림을 구성했습니다. DB 락의 근본 원인 해결이나 모든 쿼리의 전수 검증을 주장하지 않습니다.
